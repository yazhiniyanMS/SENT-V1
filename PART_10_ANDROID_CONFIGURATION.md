## PART 10 — ANDROID CONFIGURATION

### Minimum Android SDK
- **minSdkVersion 21** (Android 5.0 Lollipop)
- **targetSdkVersion 34** (Android 14)

### Required Permissions
Since the application runs in demo mode and does not access actual hardware, no dangerous permissions are required at runtime. However, for future hardware integration, the following permissions may be needed:

#### For Demo Mode (Current Implementation)
No permissions required - all data is simulated and video is loaded from assets.

#### For Future Hardware Integration
When implementing real ESP32/LoRa/sensor connections, you may need to add:

1. **Internet Access** (for WiFi/Ethernet communication):
   ```xml
   <uses-permission android:name="android.permission.INTERNET" />
   ```

2. **Access Network State** (to check connectivity):
   ```xml
   <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
   ```

3. **Bluetooth** (if using Bluetooth for sensor communication):
   ```xml
   <uses-permission android:name="android.permission.BLUETOOTH" />
   <uses-permission android:name="android.permission.BLUETOOTH_ADMIN" />
   <!-- For Android 12+ -->
   <uses-permission android:name="android.permission.BLUETOOTH_SCAN" />
   <uses-permission android:name="android.permission.BLUETOOTH_CONNECT" />
   <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
   ```

4. **Location** (for GPS functionality when using real GPS):
   ```xml
   <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
   <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
   ```

5. **Camera** (for future direct camera access, though we'll use video_player for streams):
   ```xml
   <uses-permission android:name="android.permission.CAMERA" />
   ```

### Current Configuration (Demo Mode)
Since we're using demo mode with asset-based video and simulated data, the application works without requesting any dangerous permissions.

### AndroidManifest.xml (Auto-generated by Flutter)
The Flutter template creates a basic AndroidManifest.xml that includes:
- Internet permission (needed for flutter_map tiles)
- Standard activity configuration

If you need to add additional permissions for future hardware integration, you would modify:
`android/app/src/main/AndroidManifest.xml`

### Gradle Configuration
The Flutter template uses appropriate Gradle settings for Android compatibility. No modifications are needed for the demo version.

### Important Notes
1. The application uses `flutter_map` which loads tiles from OpenStreetMap, requiring internet permission (already included in Flutter's default manifest).
2. Video playback uses the `video_player` plugin which works with asset-based videos without special permissions.
3. For future ESP32-CAM integration using MJPEG/HTTP streams, internet permission will be sufficient.
4. Location permissions are only needed if implementing real GPS functionality - demo mode uses simulated coordinates.
